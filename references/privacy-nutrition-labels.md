# Privacy nutrition labels: data type mapping

Evidence-backed mapping from what this app actually collects to Apple's App Privacy questionnaire and Google Play's Data Safety form, so both storefronts declare the same underlying facts at the correct granularity. Doc only — no runtime behavior depends on this file.

Phase 2 (transcribing this into the actual consoles) is manual, human work — not automated by an agent. Do it in App Store Connect's App Privacy questionnaire and Play Console's Data Safety form, using the exact section names below. Each table's columns match that platform's actual form fields, so transcription should be mechanical.

Apple and Google use different vocabulary for the same pair ("Coarse Location" vs. "Approximate location"), and both are now declared on both platforms — but for different reasons. iOS declares Coarse because `isLocationGated()` accepts and uses a reduced-accuracy grant. Android declares Approximate even though `isLocationGated()` rejects coarse-only grants (`android?.accuracy !== 'fine'`) — because `ACCESS_COARSE_LOCATION` is manifest-merged by `expo-location` regardless of whether the app ever consumes a coarse fix.

## Re-audit when

Any of the following changes the facts above and should trigger a re-check of this doc before the next store submission:

- A new permission is added to `app.json` (iOS `infoPlist` keys, Android `permissions` array).
- A new Expo/Config plugin is added (its bundled native manifest may merge in permissions the app never explicitly declared — this is exactly how location's Approximate/Precise split was discovered).
- A new analytics event or property is added in `src/lib/analytics/analytics.ts`, especially anything that could carry PII.
- Any of the three Facebook SDK auto-collection flags (`isAutoInitEnabled`, `advertiserIDCollectionEnabled`, `autoLogAppEventsEnabled`) flips to `true`.
- A new sign-in provider or account-linked data model is added.
- `isCameraGated()` / `isLocationGated()` in `src/screens/consent/index.tsx` change what accuracy/status is accepted — that logic is the evidence source for several rows above.

Same staleness-trigger pattern as `docs/design-decisions/using-design-decisions.md` — applied here because this file, unlike that folder, is a `references/` doc, not current-state UI/UX.
