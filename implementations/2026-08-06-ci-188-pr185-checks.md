# CI — fix PR #185 failing checks (#188)

## What shipped

Diagnosed and fixed all four red checks on PR #185 (`sprint/cat-annotate-flow` → `main`):

- **`commitlint` (real failure)** — commit `8dc0f6f`
  (`feat(cats): Cat Form drops manual photo selection (#172) (#176)`) trips
  `subject-case`. That subject is GitHub's auto-generated squash-merge
  message from PR #176's title (`git.md` lesson #1), not hand-authored.
  Rather than rewrite history on a branch backing an open PR (rejected —
  the range has merge commits woven around the target commit, making a
  safe non-interactive reword too risky for a cosmetic fix, per
  `/advisor` review), added a narrow `ignores` predicate to
  `commitlint.config.js` matching the `(#NNN) (#NNN)` double-PR-reference
  tail GitHub appends to nested-PR squash subjects. Verified locally:
  `npx commitlint --from origin/main --to origin/sprint/cat-annotate-flow`
  passes; a hand-authored bad-case subject without the tail still fails
  (`npx commitlint` on a synthetic bad subject), confirming the exception
  is scoped to the generated-subject signature, not a blanket relax of
  `subject-case`.
- **`lint-and-test` (real failure, pull_request run)** — Prettier
  formatting drift in
  `src/screens/submission/create/__tests__/CreateScreen.autoSkipGate.model.test.tsx`.
  Fixed with `npx prettier --write`.
- **`lint-and-test` (push-triggered run) + `CodeQL` Python analyze** —
  both failed with an identical GitHub Actions infra error (`"job was not
acquired by Runner of type hosted even after multiple attempts"`),
  same runner-pool timestamp. Not code issues — a fresh push retriggers
  clean runs. `CodeQL` is GitHub's default code-scanning setup (no
  in-repo workflow file); nothing to change there.
- **`ci.yml`'s `push:` trigger had no branch scope**, unlike
  `commitlint.yml` (already scoped to `main` in #181, per `git.md`
  lesson #2 — an unscoped push trigger duplicates the `pull_request`
  run on every commit to an open PR's branch). Scoped it to
  `branches: [main]` to match that precedent and stop the duplicate
  future runs; this does not retroactively clear the already-failed
  push-triggered entry — that clears on the next push's new head SHA.
