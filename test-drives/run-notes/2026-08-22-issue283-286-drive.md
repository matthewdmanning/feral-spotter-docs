## Blocker hit first: real Google Sign-In fails

`EXPO_PUBLIC_AUTH_MOCK=false` in `.env.local` at session start — real Firebase Auth active. `Continue with Google` consistently failed:

- First attempt (stale `google-services.json`, Jul 27): `NO_GOOGLE_ID_TOKEN` — account picker completes, but `response.data.idToken` comes back empty.
- Verified `.env.local`'s `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID` matches the type-3 OAuth client in `google-services.json`, and the debug keystore's SHA-1 (`5E:8F:16:...`) matches the type-1 Android OAuth client's `certificate_hash` — config is correct, not a key-mismatch.
- User supplied a freshly re-downloaded `google-services.json` — byte-identical to the existing repo copy (same OAuth client IDs, same cert hash). Copied into both `google-services.json` and `android/app/google-services.json` anyway, cleared app data, retried.
- Retry surfaced a different, more specific error: `[auth/unknown] An internal error has occurred. [ API key expired. Please renew the API key. ]`. Root cause: the Firebase Auth API key embedded in `google-services.json` (`api_key[].current_key`) is expired at Google's end — same key in both the old and newly-downloaded file, so the re-download happened before the key was actually renewed in Cloud Console. Value intentionally not recorded here — see `.agents/secrets.md` if it needs cross-referencing later.
- **Not fixable from this repo.** Needs the key renewed/regenerated in Google Cloud Console → APIs & Services → Credentials, then a fresh `google-services.json` re-download (will carry a new `current_key`).

Worked around by flipping `EXPO_PUBLIC_AUTH_MOCK=true` for the remainder of the drive (reverted to `false` at the end — file is gitignored, no repo state changed). Mock auth's stub UID isn't a real authenticated Firebase user, so real Storage uploads correctly get rejected (`[storage/unauthorized]`) during this session — expected artifact of the workaround, not a new bug.
